# Portfolio 1: Database Design and Modelling

## 1. Project Overview

This portfolio develops the database design for FinCore Payments, a simulated fintech payment processing platform.

The objective is to design a relational database that stores customer information, merchants, payment terminals, payment transactions and transaction reversals.

## 2. Objectives

- Identify the main database entities and their attributes.
- Design an Entity-Relationship Diagram (ERD).
- Develop a relational database schema.
- Define primary keys, foreign keys and integrity constraints.
- Explain database normalisation.
- Implement and test the database using PostgreSQL.

## 3. Selected Case Study

FinCore Payments is a fictional payment processing platform used to record and monitor electronic payment transactions. The database will support transaction reporting, response-code analysis and reversal tracking.

All data used in this project will be fictional.

## 4. Planned Deliverables

- Entity-Relationship Diagram (ERD)
- SQL schema scripts
- Primary key and foreign key definitions
- Integrity constraints
- Normalisation explanation
- Test data and query results
- Screenshots of the implementation
