# Portfolio 4: NoSQL and Advanced Data Models

## 1. Project Overview

This portfolio explores NoSQL data modelling using the FinCore Payments simulated fintech payment processing platform.

The objective is to implement a suitable NoSQL data model, store sample payment transaction events, execute queries and explain why the selected model is appropriate for the use case.

## 2. Objectives

- Understand the differences between relational and NoSQL databases.
- Design a NoSQL model for payment transaction events.
- Implement a document-based data model using MongoDB.
- Insert fictional transaction documents.
- Query and filter transaction records.
- Explain the suitability, advantages and limitations of the selected model.
- Capture evidence of the implementation and query results.

## 3. Selected Case Study

FinCore Payments is a fictional payment processing platform that records electronic payment transactions between customers and merchants.

MongoDB will be explored as a complementary database for transaction event records, which may contain varying attributes such as response details, processing metadata and event timestamps.

The relational database designed in Portfolio 1 remains the primary structured data model for this project.

## 4. Planned Deliverables
