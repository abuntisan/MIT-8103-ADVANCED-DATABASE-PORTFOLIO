# Portfolio 3: Transactions and Concurrency

## 1. Project Overview

This portfolio explores database transactions and concurrency control using the FinCore Payments simulated fintech payment processing platform.

The objective is to demonstrate how database transactions maintain data integrity and how PostgreSQL manages operations that occur simultaneously.

## 2. Objectives

- Demonstrate transaction control using COMMIT and ROLLBACK.
- Test successful and unsuccessful database operations.
- Examine transaction isolation.
- Demonstrate a concurrency issue or a mechanism for controlling concurrent operations.
- Explain how database transactions protect data integrity.
- Capture practical evidence of the tests and their results.

## 3. Selected Case Study

FinCore Payments is a fictional payment processing platform that records payment transactions between customers and merchants.

This portfolio will use PostgreSQL to demonstrate safe database operations involving payment records and, where appropriate, account balances.

## 4. Planned Deliverables

- SQL transaction scripts
- COMMIT and ROLLBACK examples
- Transaction isolation tests
- Concurrency test scripts or examples
- Screenshots of execution results
- Explanation of the observed behaviour
- Technical analysis and conclusions
